ÉTAPE 4: ANALYSER LES LOGS

  POST /api/v1/sales ...

  ✅ [Manual Sync] mouvements_stock synchronisé: 640
  🔄 [Manual Sync] stock_boutiques trouvé: 122
  ✅ [Manual Sync] stock_boutiques synchronisé: 122
  ✅ [Sync] Synchronisation manuelle terminée
  📤 Push 3 opération(s) vers Neon...

→ PARFAIT! La synchronisation fonctionne.


CAS B: Aucun log de sync (❌ PROBLÈME)
────────────────────────────────────────────────────────────────────
  POST /api/v1/sales ...
  📤 Push 2 opération(s) vers Neon...
  (pas de logs 🔧 [Sync])

→ Le code de sync ne s'exécute pas.

Causes possibles:
  1. CLOUD_DB_URL non défini
  2. Erreur avant le code de sync
  3. Backend pas redémarré

Actions:
  • Vérifier: cat backend\.env | Select-String "CLOUD_DB_URL"
  • Chercher des erreurs dans les logs
  • Redémarrer complètement le backend


CAS C: Sync démarre mais mouvement non trouvé (⚠️  PROBLÈME)
────────────────────────────────────────────────────────────────────
  POST /api/v1/sales ...
  🔧 [Sync] Début de la synchronisation manuelle...
  🔧 [Sync] Traitement produit 837, type: physique
  ⚠️  [Manual Sync] Mouvement de stock non trouvé pour produit 837

→ Le mouvement de stock n'a pas été créé dans la transaction.

Actions:
  • Vérifier dans SQLite:
    SELECT * FROM mouvements_stock 
    WHERE produit_id = 837 
    ORDER BY date_modification DESC 
    LIMIT 5;
  
  • Si le mouvement existe, le problème est dans la requête findFirst
  • Si le mouvement n'existe pas, le problème est dans la transaction


CAS D: Erreur de sync (❌ ERREUR)
────────────────────────────────────────────────────────────────────
  POST /api/v1/sales ...
  🔧 [Sync] Début de la synchronisation manuelle...
  ❌ Erreur sync manuelle: ...
     Stack: ...

→ Erreur dans le code de synchronisation.

Actions:
  • Copier l'erreur complète
  • Analyser le message d'erreur
  • Vérifier la connexion Neon


ÉTAPE 5: VÉRIFIER DANS NEON
═══════════════════════════════════════════════════════════════════

Après une vente réussie, vérifier dans Neon:

SELECT 
  ms.id,
  ms.produit_id,
  p.nom as produit,
  ms.type_mouvement,
  ms.changement_quantite,
  ms.date_modification,
  sb.quantite_disponible as stock_actuel
FROM mouvements_stock ms
JOIN produits p ON p.id = ms.produit_id
LEFT JOIN stock_boutiques sb ON sb.produit_id = ms.produit_id
WHERE ms.date_modification > NOW() - INTERVAL '5 minutes'
ORDER BY ms.date_modification DESC;

Résultat attendu:
  • Mouvement de stock avec changement_quantite négatif
  • Stock boutique avec quantité mise à jour
  • date_modification récente
