  transactions ($transaction). C'est une limitation de Prisma.
  
  Documentation: https://www.prisma.io/docs/concepts/components/prisma-client/client-extensions
  "Extensions are not inherited by interactive transactions"

  ✅ Synchronisation manuelle APRÈS la transaction

   SELECT 
     ms.id,
     ms.produit_id,
     p.nom as produit_nom,
     ms.type_mouvement,
     ms.changement_quantite,
     ms.date_modification,
     sb.quantite_disponible as stock_actuel
   FROM mouvements_stock ms
   JOIN produits p ON p.id = ms.produit_id
   LEFT JOIN stock_boutiques sb ON sb.produit_id = ms.produit_id
   WHERE ms.date_modification > NOW() - INTERVAL '2 minutes'
   ORDER BY ms.date_modification DESC;

RÉSULTAT ATTENDU:
  • Mouvement de stock créé avec changement_quantite négatif
  • Stock boutique mis à jour avec la nouvelle quantité
  • date_modification récente (< 2 minutes)

Les hooks Prisma ($extends) sont excellents MAIS:
  ❌ Ne fonctionnent pas dans les transactions
  ❌ Limitation documentée de Prisma
  ❌ Pas de solution simple avec $extends

Alternatives considérées:
  1. Extensions de transaction → Trop complexe, non documenté
  2. Triggers PostgreSQL → Idéal mais nécessite PostgreSQL partout
  3. Sync manuelle → Simple, fonctionne partout ✅ CHOISI
