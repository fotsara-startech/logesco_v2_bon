Scénario 1: Aucun log de sync
  Logs:
    POST /api/v1/sales ...
    (rien d'autre)
  
  Cause possible:
    • CLOUD_DB_URL non défini
    • Code de sync pas exécuté (erreur avant)
  
  Vérifier:
    cat backend\.env | Select-String "CLOUD_DB_URL"

Scénario 2: Sync démarre mais mouvement non trouvé
  Logs:
    🔧 [Sync] Début de la synchronisation manuelle...
    🔧 [Sync] Traitement produit 837, type: physique
    ⚠️  [Manual Sync] Mouvement de stock non trouvé pour produit 837
  
  Cause possible:
    • Mouvement de stock pas créé dans la transaction
    • Erreur dans la transaction
  
  Vérifier:
    SELECT * FROM mouvements_stock 
    WHERE produit_id = 837 
    ORDER BY date_modification DESC 
    LIMIT 5;

Scénario 3: Erreur de sync
  Logs:
    🔧 [Sync] Début de la synchronisation manuelle...
    ❌ Erreur sync manuelle: ...
       Stack: ...
  
  Cause possible:
    • Erreur dans syncService.enqueue()
    • Problème de connexion Neon
  
  Action:
    Copier l'erreur complète et analyser

Scénario 4: CLOUD_DB_URL non défini
  Logs:
    POST /api/v1/sales ...
    ℹ️  [Sync] CLOUD_DB_URL non défini, sync manuelle ignorée
  
  Cause:
    • Variable d'environnement manquante
  
  Solution:
    Vérifier backend\.env et redémarrer

Après la vente, vérifier dans Neon:

-- Mouvements de stock récents
SELECT 
  ms.id,
  ms.produit_id,
  p.nom as produit,
  ms.type_mouvement,
  ms.changement_quantite,
  ms.date_modification
FROM mouvements_stock ms
JOIN produits p ON p.id = ms.produit_id
WHERE ms.date_modification > NOW() - INTERVAL '5 minutes'
ORDER BY ms.date_modification DESC;

-- Stock boutiques récents
SELECT 
  sb.id,
  sb.produit_id,
  p.nom as produit,
  sb.quantite_disponible,
  sb.date_modification
FROM stock_boutiques sb
JOIN produits p ON p.id = sb.produit_id
WHERE sb.date_modification > NOW() - INTERVAL '5 minutes'
ORDER BY sb.date_modification DESC;
